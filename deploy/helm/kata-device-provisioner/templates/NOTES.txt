The dispatcher creates one Job per node and labels each node that succeeds.

Watch it:

  kubectl -n {{ .Release.Namespace }} logs -f job/{{ include "kata-device-provisioner.profileResourceName" (dict "root" . "suffix" "provision-dispatcher") }}
  kubectl -n {{ .Release.Namespace }} logs -l kata-device-provisioner/stage=provision --tail=-1 --prefix

See what it did:

  kubectl get nodes -L {{ .Values.ccModeStateLabel }}

A node is provisioned when it carries that label. If one is missing, its Job's
log names the device and the reason; nothing was changed on a node that failed.

To undo it, `helm uninstall` removes the modprobe configuration and releases the
devices, but leaves CC mode alone: reverting it costs a GPU reset per device.
Set ccMode to "off" and upgrade first if you want the hardware back as it was.
